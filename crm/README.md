# Контур ремонта — первая версия CRM

Приложение для одной компании с несколькими филиалами. Python 3.12+, без сторонних зависимостей. Исходная страница репозитория не изменена; CRM находится отдельно в `crm/`.

## Запуск

Из `/workspace/test`:

```sh
python crm/server.py
```

Сервер по умолчанию слушает `127.0.0.1:8000`. При первом открытии создайте владельца компании и первый филиал. Тестовые учётные записи и клиентские данные в рабочую базу не добавляются. Пароль минимум 12 символов. Затем создайте филиалы и сотрудников в соответствующих разделах.

Переменные: `CRM_DB` — путь SQLite (по умолчанию `crm/data.sqlite3`), `PORT` — порт, `CRM_HOST` — адрес прослушивания. За HTTPS-прокси задайте `CRM_SECURE_COOKIE=1`. Для подключения с других устройств необходимы сервер, HTTPS-прокси и доступный адрес; локальный запуск сам по себе не предоставляет доступ через интернет.

База содержит клиентские данные: не включайте её в Git; используйте защищённые резервные копии SQLite через backup API. Процессы после восстановления облачной среды нужно запускать заново.

## Реализовано

- Создание компании, вход, выход, серверные сессии на 12 часов; пароли scrypt, HttpOnly cookies.
- Владелец: все филиалы, добавление/отключение сотрудников. Отключение отзывает сессии.
- Приёмщик: создание и просмотр заказов только доступных филиалов, оплата, выдача.
- Мастер: просмотр назначенных заказов своего филиала, работы, материалы, статусы и комментарии. Приём оплаты и выдача запрещены.
- Общие справочники устройств, внешнего состояния и неисправностей: ввод новых вариантов, выбор сохранённых, несколько меток состояния и неисправностей. Дубли вариантов без учёта регистра и лишних пробелов не создаются.
- Поиск клиентов по части ФИО или телефона с подстановкой обоих полей. Клиенты общие для компании и доступны владельцу/приёмщику; доступ к самим заказам по-прежнему ограничен филиалами. Мастер не имеет доступа к поиску и справочникам.
- Номера российских клиентов с 8/+7 и разным оформлением объединяются по нормализованному номеру. При совпадении номера сохраняется последнее введённое ФИО; исторические заказы не меняются.
- Карточка заказа: клиент, телефон, устройство, серийный номер, внешний вид, комплектация, неисправность, мастер, срок, предварительная стоимость.
- Настроенный начальный набор статусов, журнал изменений, позиции работ и материалов с ценами и гарантией.
- Оплата наличными, картой или переводом как учётная запись операции (без платёжной интеграции). Выдача с задолженностью блокируется.
- Денежные суммы хранятся в копейках. Конкурирующая смена статуса обнаруживается по версии заказа.
- Поиск, фильтры по филиалу/состоянию, список клиентов по доступным заказам, печать карточки, адаптивная вёрстка.

## Проверки

```sh
python crm/test_workflow.py
node --check crm/static/app.js
```

Интеграционный тест поднимает отдельный сервер с временной базой: вход, филиалы, роли, ограничения доступа, работы, оплата, запрет выдачи с долгом, конфликт версий, выдача и отзыв доступа. Рабочую базу тест не меняет.

## Ограничения первой версии

Это основа для разработки, а не готовая замена LiveSklad для большой сети. Ещё не реализованы: полноценное редактирование карточек клиентов, изменение реквизитов заказа после создания, редактирование прав и профиля сотрудников, смена/восстановление пароля, настройка статусов, передача заказов, складской учёт и резервирование, розничные продажи, возвраты/скидки, вложения, уведомления, аналитика и юридические шаблоны документов. Позиция «Материал» пока не списывает складской остаток. Печать карточки не является фискальным чеком.

Перед рабочим запуском нужны PostgreSQL и миграции для нагрузки большой сети, промышленный HTTP-сервер, HTTPS, защита входа от перебора, резервное копирование с проверкой восстановления и проверка конкурентных финансовых операций. Не храните пароли от аккаунтов клиентов в комментариях.

## Обновление установленной версии на Windows

1. В окне сервера нажмите Ctrl+C.
2. Скопируйте `data.sqlite3` в отдельную папку как резервную копию.
3. Скачайте свежий ZIP ветки `crm/initial-version` с GitHub и распакуйте в отдельное место.
4. Скопируйте содержимое новой папки `crm` поверх установленной папки `crm`. Ваш `data.sqlite3` не удаляйте и не заменяйте: в архиве GitHub базы нет.
5. Выполните `python server.py` в установленной папке и обновите страницу браузера сочетанием Ctrl+F5.

При первом запуске после обновления справочники и клиенты автоматически пополнятся из старых заказов. Их данные, сотрудники, пароли и платежи сохраняются. Перенос выполняется один раз; повторный запуск не создаёт дубли. Если два старых заказа содержат один номер в разных форматах, в клиентской базе используется ФИО из более позднего заказа. Не удаляйте базу для обновления приложения.

В новом заказе найдите клиента по фамилии или номеру и нажмите подходящий результат. Затем выберите устройство из подсказок или введите своё. Для состояния и неисправностей выбирайте/вводите отдельные варианты и нажимайте «Добавить»; метку можно убрать крестиком. Новый вариант сохраняется в справочник сразу. Введённый, но ещё не добавленный вариант также будет включён при создании заказа.
