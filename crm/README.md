# Контур ремонта — первая версия CRM

Приложение для одной компании с несколькими филиалами. Python 3.12+, без сторонних зависимостей. Исходная страница репозитория не изменена; CRM находится отдельно в `crm/`.

## Запуск

Из `/workspace/test`:

```sh
python crm/server.py
```

Сервер по умолчанию слушает `127.0.0.1:8000`. При первом открытии создайте владельца компании и первый филиал. Тестовые учётные записи и клиентские данные в рабочую базу не добавляются. Пароль минимум 12 символов. Затем создайте филиалы и сотрудников в соответствующих разделах.

Переменные: `CRM_DB` — путь SQLite (по умолчанию `crm/data.sqlite3`), `PORT` — порт, `CRM_HOST` — адрес прослушивания. За HTTPS-прокси задайте `CRM_SECURE_COOKIE=1`. Для подключения с других устройств необходимы сервер, HTTPS-прокси и доступный адрес; локальный запуск сам по себе не предоставляет доступ через интернет.

База содержит клиентские данные: не включайте её в Git; используйте защищённые резервные копии SQLite через backup API. Процессы после восстановления облачной среды нужно запускать заново.

## Реализовано

- Создание компании, вход, выход, серверные сессии на 12 часов; пароли scrypt, HttpOnly cookies.
- Владелец: все филиалы, добавление/отключение сотрудников. Отключение отзывает сессии.
- Приёмщик: создание и просмотр заказов только доступных филиалов, оплата, выдача.
- Мастер: просмотр назначенных заказов своего филиала, работы, материалы, статусы и комментарии. Приём оплаты и выдача запрещены.
- Общие справочники устройств, внешнего состояния и неисправностей: ввод новых вариантов, выбор сохранённых, несколько меток состояния и неисправностей. Дубли вариантов без учёта регистра и лишних пробелов не создаются.
- Поиск клиентов по части ФИО или телефона с подстановкой обоих полей. Клиенты общие для компании и доступны владельцу/приёмщику; доступ к самим заказам по-прежнему ограничен филиалами. Мастер не имеет доступа к поиску клиентов и справочникам приёмки, но может пополнять и использовать справочник работ.
- Маска телефона `+7 (XXX) XXX-XX-XX`: ввод, вставка и проверка полноты; сервер принимает только 11 цифр с кодом +7, номера с 8 нормализует.
- Номера российских клиентов с 8/+7 и разным оформлением объединяются по нормализованному номеру. При совпадении номера сохраняется последнее введённое ФИО; исторические заказы не меняются.
- Карточка заказа: клиент, телефон, устройство, серийный номер, внешний вид, комплектация, неисправность, мастер, срок, предварительная стоимость.
- Настроенный начальный набор статусов, журнал изменений, позиции работ и материалов с ценами и гарантией.
- Кнопки «Выдать» и «Выдать без ремонта» открывают выбор способа оплаты. Подтверждение атомарно записывает остаток оплаты (с учётом прежних платежей), статус и начисления мастерам. Повторная выдача запрещена. Это учёт оплаты, без платёжной интеграции; факт получения денег подтверждает сотрудник. Отдельный блок приёма оплаты убран. Старый API платежей сохранён для совместимости с предоплатами.
- Денежные суммы хранятся в копейках. Конкурирующая смена статуса обнаруживается по версии заказа.
- Поиск, фильтры по филиалу/состоянию, список клиентов по доступным заказам, адаптивная вёрстка.
- Сохраняемое заключение диагностики с защитой от перезаписи устаревшей версией.
- Три отдельных документа: акт приема на диагностику, акт диагностики с сохранённым заключением, акт выполненных работ. Документы открываются в новой вкладке и печатаются/сохраняются в PDF через кнопку браузера.
- В акте выполненных работ — только строки работ, их количество, цена, сумма и гарантия, плюс реквизиты заказа и подписи. Запчасти, закупочные цены, прибыль и старые строки типа «Материал» не выводятся; итог документа равен сумме работ.
- Общий справочник названий работ. Новые работы сохраняются автоматически при добавлении в заказ или отдельной кнопкой. Старые работы автоматически переносятся при обновлении.
- Склад запчастей отдельно по филиалам: артикул, название, поступления, количество и средневзвешенная закупочная цена. Владельцу и приёмщику доступны поступления в их филиалы, мастеру — просмотр склада и списание к назначенной работе.
- Кнопка «Запчасть» в строке работы списывает количество со склада филиала заказа. Себестоимость сохраняется на момент списания и вычитается из прибыли работы; цена и сумма к оплате клиентом не меняются. Остатки не могут стать отрицательными, поступления/списания сохраняются в журнале движений.
- Транзакции записей сериализованы SQLite, поэтому одновременные списания не могут использовать один остаток дважды. Проверяется принадлежность работы заказу, запчасти филиалу и права сотрудника.

## Проверки

```sh
python crm/test_workflow.py
node --check crm/static/app.js
```

Интеграционный тест поднимает отдельный сервер с временной базой: вход, филиалы, роли, ограничения доступа, работы, оплата, запрет выдачи с долгом, конфликт версий, выдача и отзыв доступа. Рабочую базу тест не меняет.

## Ограничения первой версии

Это основа для разработки, а не готовая замена LiveSklad для большой сети. Ещё не реализованы: полноценное редактирование карточек клиентов, изменение реквизитов заказа после создания, редактирование прав и профиля сотрудников, смена/восстановление пароля, настройка статусов, передача заказов, перемещения запчастей между филиалами, инвентаризация и резервирование, розничные продажи, возвраты/скидки, вложения, уведомления, аналитика и настройка реквизитов/шаблонов документов. Старые позиции «Материал» сохранены для совместимости и не связаны со складом; новые запчасти добавляйте кнопкой в строке работы. Отмена ошибочного списания и возврат запчастей на склад пока не реализованы. Печатные акты не являются фискальными чеками.

Перед рабочим запуском нужны PostgreSQL и миграции для нагрузки большой сети, промышленный HTTP-сервер, HTTPS, защита входа от перебора, резервное копирование с проверкой восстановления и проверка конкурентных финансовых операций. Не храните пароли от аккаунтов клиентов в комментариях.

## Обновление установленной версии на Windows

1. В окне сервера нажмите Ctrl+C.
2. Скопируйте `data.sqlite3` в отдельную папку как резервную копию.
3. Скачайте свежий ZIP ветки `crm/initial-version` с GitHub и распакуйте в отдельное место.
4. Скопируйте содержимое новой папки `crm` поверх установленной папки `crm`. Ваш `data.sqlite3` не удаляйте и не заменяйте: в архиве GitHub базы нет.
5. Выполните `python server.py` в установленной папке и обновите страницу браузера сочетанием Ctrl+F5.

При первом запуске после обновления справочники и клиенты автоматически пополнятся из старых заказов. Их данные, сотрудники, пароли и платежи сохраняются. Перенос выполняется один раз; повторный запуск не создаёт дубли. Если два старых заказа содержат один номер в разных форматах, в клиентской базе используется ФИО из более позднего заказа. Не удаляйте базу для обновления приложения.

В новом заказе найдите клиента по фамилии или номеру и нажмите подходящий результат. Затем выберите устройство из подсказок или введите своё. Для состояния и неисправностей выбирайте/вводите отдельные варианты и нажимайте «Добавить»; метку можно убрать крестиком. Новый вариант сохраняется в справочник сразу. Введённый, но ещё не добавленный вариант также будет включён при создании заказа.

## Работа со складом и документами

1. В «Склад запчастей» нажмите «Добавить запчасть», укажите филиал, название, артикул, количество и закупочную цену за штуку. Повторное поступление для позиции оформляйте кнопкой «Поступление». Одинаковый артикул может существовать в разных филиалах.
2. В заказе откройте «Работы и материалы», выберите/введите название работы, цену клиенту, количество и гарантию. Добавьте работу.
3. В её строке нажмите «Запчасть», выберите позицию и количество, затем «Списать и вычесть стоимость». Например, работа 5 500 ₽ и запчасть 1 000 ₽: клиенту 5 500 ₽, прибыль до других расходов 4 500 ₽. Зарплата, налоги и прочие расходы здесь не учитываются.
4. Заполните поле «Заключение диагностики» и нажмите «Сохранить заключение». Только сохранённое значение попадёт в акт диагностики.
5. Выберите нужный акт в блоке «Документы для печати». Акт выполненных работ содержит только работы; складские детали остаются внутри CRM.

При обновлении копируйте всю папку `crm`, включая новый `documents.py`, сохраняя свою базу. Миграция добавит поле диагностики и таблицы склада автоматически, без очистки старых заказов.

## Компактная карточка, выдача и зарплата

- На главной доступны даты «с/по» включительно, фильтр филиала и кнопки «Сегодня», «7 дней», «Месяц» (текущий календарный месяц). Границы суток — московские. Показаны количество принятых устройств по дате создания заказа и выданных по дате выдачи, сумма работ выданных ремонтов, запчасти, прибыль и начисления по мастерам. Строки старого типа «Материал» входят в оплату заказа, но не в сумму работ и зарплату.
- Зарплата — начисление, а не факт выплаты. Для каждой работы выбирается пользователь-мастер с доступом к филиалу. Несколько работ одного заказа могут принадлежать разным мастерам. Исполнитель работы видит заказ, даже если основной мастер заказа другой. Мастер на главной видит только свои начисления; приёмщик — по доступным филиалам, владелец — по сети.
- Чистая прибыль работы здесь = цена работы × количество − себестоимость списанных к ней запчастей, до налогов/аренды/прочих расходов. Доля мастера — 40%, сервиса — остаток 60%, округление до копейки на каждую работу. При убытке доля мастера нулевая, убыток относится сервису. Начисления фиксируются при выдаче и не зависят от будущих закупочных цен.
- Старым работам автоматически назначается основной мастер их заказа. Если он отсутствовал, в старых начислениях видна строка «Не назначен»; для новых/ещё не выданных заказов используйте кнопку «Мастер» в строке работы. Выдача запрещена, пока у каждой работы не назначен исполнитель.
- При обновлении дата выдачи старых закрытых заказов берётся из истории смены статуса, при отсутствии записи — из даты создания. Эта последняя дата является приближённой. Старые начисления восстанавливаются один раз из сохранённых работ и себестоимости.
- В карточке статус находится сверху. Вкладка «Информация о заказе» содержит только клиента, телефон и неисправность. Данные устройства — во вкладке «Квитанция», работы — в отдельной вкладке. История и диагностика сворачиваются. Итог и кнопки выдачи — внизу.
- Пароль разблокировки устройства можно указать при создании квитанции, затем посмотреть во вкладке «Квитанция» кнопкой «Показать / скрыть». Он не попадает в списки заказов, журналы, отчёты и печатные акты. Это поле для доступа к устройству, не для паролей облачных аккаунтов клиента.
- Статусы «Выдан» и «Выдан без ремонта» нельзя выбрать через обычную смену статуса. Закрытый заказ нельзя повторно выдать, менять работы, списывать запчасти или переназначать мастера. При выдаче без ремонта все явно добавленные платные работы (например, диагностика) остаются к оплате; для бесплатной выдачи не добавляйте платных работ.

Копируйте все файлы обновления, включая `reporting.py` и `documents.py`, сохраняя `data.sqlite3`.
